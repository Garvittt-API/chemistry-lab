# Contributing

Thank you for considering contributing.

## Before contributing
- Read `CODE_OF_CONDUCT.md`, `SECURITY.md`, and relevant documentation.
- Open an issue or discussion before large changes.
- Do not submit copied educational content, diagrams, images or code without compatible rights and attribution.

## Code contributions
- Use a focused branch and small pull request.
- Follow existing formatting, linting, typing and testing conventions.
- Include tests for changed behavior.
- Update documentation and changelog when appropriate.
- Do not commit secrets, credentials, student personal data or real laboratory records.

## Experiment/content contributions
Every experiment proposal must include:
- Learning objectives and target level.
- Trusted references and provenance.
- Theory, equations, units and conditions.
- Equipment and chemical hazard information.
- Step-by-step educational procedure appropriate to the audience.
- Simulation model, assumptions and limitations.
- Expected/reference cases and validation tests.
- Accessibility notes and required assets with licenses.

Scientific content requires review before being marked validated or released. A pull request alone does not constitute scientific approval.

## Pull request checklist
- [ ] Scope is focused and linked to an issue/task.
- [ ] Tests and quality checks pass.
- [ ] Scientific claims have credible references where applicable.
- [ ] Safety and accessibility have been considered.
- [ ] Assets and dependencies have compatible licenses.
- [ ] Documentation and changelog are updated.
